# 学习笔记

## 阶段 0：环境与 SQL 入门

### 三个基本概念

| 概念 | 是什么 | 例子 |
|---|---|---|
| 数据库 | 按一定结构组织起来的数据本身 | `chinook.db` 文件 |
| 数据库管理系统（DBMS） | 负责存储、查询、维护数据的软件 | SQLite 引擎、MySQL |
| 客户端 | 发送 SQL、查看结果的程序 | `sqlite3.exe`、DBeaver |

- SQLite 是**嵌入式**数据库：没有独立的服务进程，DBMS 是一个函数库，编译进各个程序里。`sqlite3.exe`（3.54.1）和 Python 的 `sqlite3` 模块（3.49.1）各带一份 SQLite 引擎，操作的是同一个文件。
- MySQL 是**客户端/服务器**模式：DBMS 是一直运行的服务进程，客户端通过网络连接它（阶段 7）。
- `.db` 文件是二进制格式，直接用文本编辑器打开只能看到乱码，必须通过 DBMS 读取。

### 为什么不用 CSV / Excel 存数据

| 用文件存数据的问题 | DBMS 提供的能力 | 阶段 |
|---|---|---|
| 查找只能从头扫到尾，O(n) | 索引（B+ 树），O(log n) | 5 |
| 并发读-判断-写导致超卖、互相覆盖 | 事务和锁 | 6 |
| 写到一半崩溃，文件损坏 | 原子性：要么全做，要么全不做 | 6 |
| 非法数据（成绩 `abc`、`150`）没人拦 | 约束：规则定义在数据上，谁写都要遵守 | 2 |
| 同一份数据存多处，改一处漏一处 | 靠**设计**解决（只存一份，用 ID 引用），工具解决不了 | 1 |

- Excel 一个工作表最多 1,048,576 行。
- **SQL 是声明式语言**：只说明要什么，不说怎么找。怎么找（扫描全表还是走索引）由 DBMS 决定。Python、C++ 是命令式语言，要一步步告诉计算机怎么做。

### sqlite3 命令行

```
sqlite3 data/chinook.db     打开数据库
.headers on                 显示列名
.mode box                   用表格框显示结果
.tables                     列出所有表
.quit                       退出
```

- 以 `.` 开头的是 sqlite3 客户端自己的命令，不是 SQL，结尾不加分号。
- SQL 语句以 `;` 结尾。
- 装完新工具后要重开终端才能读到新的 PATH。VS Code 内置终端要重启整个 VS Code。
- 在单独打开的 Git Bash 窗口（mintty）里，交互模式可能会卡住，这时改用 `winpty sqlite3 ...`。

### 表、主键与查看表结构

- 表没有固有的行顺序，行靠**主键**区分，不靠「第几行」。
- 主键 = 唯一 + 非空，由 DBMS 强制执行；可以由多列组成。
- 主键用**没有业务含义**的编号（如 `CustomerId`），不用名字、邮箱：
  - 名字会重复
  - 邮箱现在不重复，不代表规则上永远不重复；而且会变，主键一变，所有引用它的行都得跟着改
- `NOT NULL` 只保证不为空，不保证不重复。
- 联合主键：`PlaylistTrack(PlaylistId, TrackId)`，单独哪一列都会重复，组合起来保证「同一首歌不会在同一个歌单里出现两次」。这种表记录的是多对多关系。
- 外键：指向另一张表主键的列。也可以引用自己所在的表（`Employee.ReportsTo` → `Employee.EmployeeId`，叫自引用）。
- 沿外键手动追踪时，每一步都用**上一步读到的外键值**去下一张表里找，编号中途会变（Track 3 → Album 3 → Artist 2）。
- 没有值就用 NULL（总经理没有上级），不要填 0 或别的假值。

| 想知道什么 | sqlite3 | DBeaver |
|---|---|---|
| 有哪些表 | `.tables` | 左侧导航 |
| 建表语句 | `.schema 表名` | 属性 → DDL |
| 列、类型、非空、主键 | `PRAGMA table_info(表名);` | 属性 → 列 |
| 表之间的关系 | `.schema` 里的 `FOREIGN KEY` | 属性 → 外键，或「图」标签 |
| 看几行数据 | `SELECT * FROM 表名 LIMIT 5;` | 「数据」标签 |

- `PRAGMA` 是 SQLite 专有的命令，要加分号，DBeaver 里也能运行；点命令只能在 sqlite3 里用。
- `PRAGMA table_info` 的 `pk` 列：0 表示不是主键，1、2…… 是该列在主键里的位置。

### SELECT 基础与排序分页

```sql
SELECT [DISTINCT] 列或表达式 AS 别名, ...
FROM 表
ORDER BY 列1 [ASC|DESC], 列2 [ASC|DESC]
LIMIT 行数 OFFSET 跳过行数;
```

处理顺序：`FROM` → `SELECT`（算列、起别名）→ `DISTINCT` → `ORDER BY` → `LIMIT/OFFSET`

| 规则 / 易错点 | 说明 |
|---|---|
| 不写 `ORDER BY`，顺序就不可依赖 | `LIMIT 5` 不等于「前 5 行」；同一张表只换选的列，DBMS 可能走索引，返回的行就变了 |
| 整数相除会截断 | `343719 / 60000` = 5，写成 `60000.0` 才得 5.73，不报错 |
| 别名用双引号 | 双引号括名字，单引号括字符串值；有空格、括号时必须加引号 |
| `ORDER BY` 能用别名 | 因为 `SELECT` 先于 `ORDER BY` 处理 |
| `DISTINCT` 作用于整行 | 看所有选出的列组合是否重复；只能紧跟在 `SELECT` 后面 |
| 多列排序 | 先比第一列，相等再比第二列；`DESC` 只管紧挨着它的那一列 |
| 分页必须配 `ORDER BY` | 否则翻页时会有行重复出现或被漏掉；`OFFSET` 很大时会变慢（阶段 5） |
| 排序列有并列值时，顺序仍不确定 | 加主键作为最后一个排序依据：`ORDER BY UnitPrice DESC, TrackId` |
| 分页公式 | 第 n 页、每页 k 条：`LIMIT k OFFSET (n - 1) * k` |
| 字符串默认按编码排序 | 大写字母排在小写字母前：`USA` 排在 `United Kingdom` 前面 |
| 程序里少用 `SELECT *` | 明确写列名，少传数据，也不怕以后表结构变化 |

- 关键字大写、名字按原样写；`--` 是注释。
- DBeaver 默认一次只取 200 行，行数以状态栏为准。

### DBeaver

- 新建连接：插头加号图标 → SQLite → 选择 `.db` 文件 → 测试连接（第一次要下载驱动）→ 完成。
- 常用的只有四样：
  - 左侧数据库导航：找到表
  - 双击表：「属性」看列，「数据」看内容
  - Ctrl + ]：打开 SQL 编辑器
  - Ctrl + Enter：执行光标所在的语句
- 界面点乱了：窗口 → 重置透视图。
- AI 助手功能在学习阶段先不开：练的就是自己把需求翻译成 SQL。
- VS Code 的 SQLite Viewer 插件只能看、不能执行 SQL，而且有缓存，改完数据后可能显示旧数据。

### Git

- 可以重新生成、重新下载的二进制文件（如 `.db`）不提交，在 README 里记录获取方法即可。
- 用 `*.db` 比忽略整个 `data/` 更精确，不会误伤以后放进 `data/` 的其他文件。
