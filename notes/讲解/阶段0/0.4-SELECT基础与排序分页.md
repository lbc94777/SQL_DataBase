# 阶段 0：SELECT 基础与排序分页

## 全貌

这一篇回答四个问题：

1. **怎么从一张表里取出想要的列？** 还能顺手算点东西、改个列名吗？

### 先指出两个容易误解的地方

> **你可能以为 SQL 像 Python 一样从上往下执行，`SELECT` 写在第一个，就第一个执行。其实不是。** DBMS 先看 `FROM` 找到表，最后才处理 `SELECT` 后面那些列。这个顺序会直接决定「哪些写法合法」，本篇最后一节专门讲。

> **你可能以为 `LIMIT 5` 就是「表里的前 5 行」。其实不写 `ORDER BY` 时，取到哪 5 行没有任何保证。** 0.3 提过表没有固有顺序，下面用实验让你亲眼看到。

在 `Track` 表上执行两条几乎一样的查询，只是选的列不同：

```sql
SELECT TrackId, Name    FROM Track LIMIT 5;
SELECT TrackId, AlbumId FROM Track LIMIT 5;
```

结果：

```
TrackId, Name 的「前 5 行」      TrackId, AlbumId 的「前 5 行」
1  For Those About To Rock      1  1
2  Balls to the Wall            6  1
3  Fast As a Shark              7  1
4  Restless and Wild            8  1
5  Princess of the Dawn         9  1
```

同一张表、同样是 `LIMIT 5`，第一条拿到的是 1～5 号，第二条拿到的却是 1、6、7、8、9 号。

原因：第二条只需要 `TrackId` 和 `AlbumId`，而 `AlbumId` 上恰好建了一个**索引**，索引里按 `AlbumId` 排好了序，并且存着对应的 `TrackId`。DBMS 判断直接读这个索引更快，于是按索引的顺序返回。索引是阶段 5 的内容，现在只需要记住结论：

**DBMS 用什么顺序读数据由它自己决定，你只要不写 `ORDER BY`，顺序就不可依赖。**想要「最长的 5 首」「最新的 10 条」，必须用 `ORDER BY` 说清楚按什么排。

### 书写习惯

- SQL 关键字不区分大小写，`select` 和 `SELECT` 一样。习惯上**关键字大写、表名列名按原样写**，一眼就能区分哪些是语法、哪些是你的数据。

- 语句长了就分行写，一个子句占一行：

```sql
SELECT Name, Milliseconds
FROM Track
ORDER BY Milliseconds DESC
LIMIT 5;
```

## 选列

```sql
SELECT 列1, 列2, ... FROM 表名;
```

- `SELECT *`：取所有列。
- `SELECT Name, UnitPrice`：只取这两列，**顺序按你写的顺序**，不必和表里的顺序一样。

`*` 在自己探索数据时很方便。但在程序里（阶段 4 用 Python 读数据），建议**明确写出需要的列**：

- 只取需要的数据，少传输、少占内存。
- 表结构以后加了列、调了列顺序，明确写列名的查询不受影响。

## 计算列

`SELECT` 后面不只能写列名，还能写**表达式**，DBMS 会对每一行计算一次。

```sql
SELECT Name, Milliseconds / 1000 FROM Track LIMIT 3;
```

能用的运算符和 C++ 一样：`+`、`-`、`*`、`/`、`%`。

### 整数除法的坑

`Milliseconds` 是毫秒，想换算成分钟：

```sql
SELECT Name, Milliseconds, Milliseconds / 60000, Milliseconds / 60000.0
FROM Track
LIMIT 3;
```

```
Name                                     Milliseconds  /60000  /60000.0
For Those About To Rock (We Salute You)  343719        5       5.72865
Balls to the Wall                        342562        5       5.7093666666666669
Fast As a Shark                          230619        3       3.84365
```

和 C++ 一样：**两个整数相除，结果是整数，小数部分直接截掉。**5.73 分钟变成了 5 分钟，而且不会有任何报错提醒你。

解决办法也和 C++ 一样：让其中一个操作数变成小数，写成 `60000.0`。

小数位太长的问题，等 0.6 学了 `ROUND` 函数就能处理。

## 列别名：AS

计算列的列名默认就是表达式本身，比如 `Milliseconds / 60000.0`，又长又难读。用 `AS` 起个名字：

```sql
SELECT Name AS 曲名, Milliseconds / 60000.0 AS 分钟
FROM Track
LIMIT 3;
```

```
曲名                                     分钟
For Those About To Rock (We Salute You)  5.72865
...
```

规则：

- `AS` 可以省略（`Name 曲名`），但写上更清楚，推荐写。
- 别名里有空格、括号等特殊字符时，要用**双引号**括起来：`AS "时长(分钟)"`。
- SQL 标准里，**双引号括的是名字（列名、别名、表名），单引号括的是字符串值**。SQLite 对别名用单引号也能容忍，但这是它的特例，换到别的数据库可能就报错了，养成用双引号的习惯。（MySQL 习惯用反引号，阶段 7 再说。）
- 别名只改变**结果里显示的列名**，不会改动表结构。

## 去重：DISTINCT

顾客都来自哪些国家？

```sql
SELECT Country FROM Customer;
```

59 位顾客就有 59 行，`USA` 出现了很多次。加上 `DISTINCT`，重复的行只保留一行：

```sql
SELECT DISTINCT Country FROM Customer;
```

### DISTINCT 作用于整行，不是单列

`DISTINCT` 写在 `SELECT` 后面紧挨着，它看的是**所有选出的列组合起来**是否重复，不是只看第一列。

```sql
SELECT DISTINCT Country, City FROM Customer;
```

这条去掉的是「国家 + 城市」都相同的行。`Brazil` 会出现好几次，因为巴西的顾客分布在好几个城市：

```
Brazil  Brasília
Brazil  Rio de Janeiro
Brazil  São José dos Campos
Brazil  São Paulo
```

不能写成 `SELECT Country, DISTINCT City`，`DISTINCT` 只能紧跟在 `SELECT` 后面。

## 排序：ORDER BY

```sql
SELECT Name, Milliseconds
FROM Track
ORDER BY Milliseconds DESC;
```

- `ASC`：升序，从小到大，**默认**，可以不写。
- `DESC`：降序，从大到小。
- 字符串按字母顺序排，数字按大小排。

### 多列排序

```sql
SELECT Country, City, LastName
FROM Customer
ORDER BY Country, City;
```

先按 `Country` 排；`Country` 相同的，再按 `City` 排。就像 C++ 里写 `sort` 的比较函数：先比第一关键字，相等时再比第二关键字。

每一列可以单独指定方向：`ORDER BY Country ASC, City DESC`。`DESC` 只管紧挨着它的那一列。

### 按计算列和别名排序

```sql
SELECT Name, Milliseconds / 1000.0 AS 秒
FROM Track
ORDER BY 秒 DESC;
```

`ORDER BY` 里可以直接用 `SELECT` 里定义的别名。为什么可以？看最后一节的执行顺序。

## 分页：LIMIT 和 OFFSET

```sql
SELECT TrackId, Name
FROM Track
ORDER BY TrackId
LIMIT 10 OFFSET 20;
```

- `LIMIT 10`：最多返回 10 行。
- `OFFSET 20`：先跳过 20 行，再开始取。

所以这条取的是排序后的第 21～30 行，也就是**每页 10 条时的第 3 页**。

网页上的「上一页、下一页」就是这样实现的：每页 `LIMIT` 条，第几页决定 `OFFSET` 跳过多少行。第 n 页的 `OFFSET` 怎么算，留在任务里。

两条规则：

- **分页必须配 `ORDER BY`**。没有确定的顺序，「第 3 页」就没有意义，翻页时可能有的行出现两次、有的行一次都没出现。
- `OFFSET` 跳过的行，DBMS 照样要一行行数过去再丢掉，所以页码很大时会变慢。更好的分页方法属于性能问题，阶段 5 再说。

## 执行顺序

一条 `SELECT` 的**书写顺序**和 DBMS 的**处理顺序**不一样。

书写顺序：

```
SELECT [DISTINCT] 列 → FROM 表 → ORDER BY → LIMIT / OFFSET
```

处理顺序：

| 步骤 | 子句 | 这一步做什么 |
|---|---|---|
| 1 | `FROM` | 确定从哪张表取数据 |
| 2 | `SELECT` | 对每一行计算要输出的列、起别名 |
| 3 | `DISTINCT` | 去掉重复的行 |
| 4 | `ORDER BY` | 排序 |
| 5 | `LIMIT / OFFSET` | 跳过若干行，截取若干行 |

这个顺序能解释好几个现象：

- **`ORDER BY` 能用别名**：别名在第 2 步就定义好了，第 4 步排序时当然认识它。
- **先排序、后截取**：`ORDER BY ... LIMIT 5` 是「全部排好序之后取前 5 个」，不是「随便取 5 个再排序」。所以它能正确找出最长的 5 首歌。
- **`DISTINCT` 在 `LIMIT` 之前**：`SELECT DISTINCT Country ... LIMIT 5` 得到的是 5 个不同的国家，而不是先取 5 行再去重。

严格来说，DBMS 实际执行时可以换别的方法（比如上面走索引），但**结果必须和按这个顺序处理得到的结果一样**。理解 SQL 时，按这张表的顺序想就对了。

0.5 加入 `WHERE` 后，这张表会多一行，到时你会遇到一个「`ORDER BY` 能用别名，`WHERE` 却不能用」的现象，原因同样在这里。

## 参考答案

### 第 1 题

```sql
SELECT Name, Composer, UnitPrice
FROM Track
ORDER BY TrackId
LIMIT 10;
```

### 第 2 题

```sql
SELECT Name                  AS 曲名,
       Milliseconds / 60000.0 AS "时长(分钟)",
       Bytes / 1024.0 / 1024  AS "大小(MB)"
FROM Track;
```

全用整数（`/ 60000`、`/ 1024 / 1024`）时，小数部分被截掉：第 1 首歌显示 5 分钟、10 MB，实际是 5.73 分钟、10.65 MB。

### 第 3 题

```sql
SELECT DISTINCT Country
FROM Customer
ORDER BY Country;
```

共 **24** 个国家。

注：结果里 `USA` 排在 `United Kingdom` 前面，因为 SQLite 默认按字符编码比较，大写 `S` 的编码比小写 `n` 小。

### 第 4 题

```sql
SELECT DISTINCT GenreId FROM Track;                -- 25 行
SELECT DISTINCT MediaTypeId FROM Track;            -- 5 行
SELECT DISTINCT GenreId, MediaTypeId FROM Track;   -- 38 行
```

- 最小可能值 **25**：每种流派至少出现一次，所以组合数不可能少于两者中较大的那个。
- 最大可能值 **25 × 5 = 125**：每种流派都有全部 5 种格式。
- 实际是 38：大多数流派只用到一两种格式，只有实际出现过的组合才会被计入。

### 第 5 题

```sql
SELECT Name AS 曲名, Milliseconds / 60000.0 AS 分钟
FROM Track
ORDER BY 分钟 DESC
LIMIT 5;
```

| 曲名 | 分钟 |
|---|---|
| Occupation / Precipice | 88.12 |
| Through a Looking Glass | 84.81 |
| Greetings from Earth, Pt. 1 | 49.34 |
| The Man With Nine Lives | 49.28 |
| Battlestar Galactica, Pt. 2 | 49.27 |

### 第 6 题

```sql
SELECT FirstName, LastName, Country, City
FROM Customer
ORDER BY Country, City, LastName DESC;
```

检查点：巴西圣保罗（São Paulo）的两位顾客，Rocha 应排在 Martins 前面。

### 第 7 题

```sql
SELECT TrackId, Name
FROM Track
ORDER BY TrackId
LIMIT 15 OFFSET 45;
```

第 4 页第一首是 **TrackId = 46**（Mary Jane），最后一首是 60。

公式：第 n 页（每页 k 条）是 `LIMIT k OFFSET (n - 1) * k`。

### 第 8 题

- **不能保证。**`UnitPrice` 只有 0.99 和 1.99 两种值，其中 1.99 的有 213 首。`ORDER BY UnitPrice DESC` 只规定了「1.99 排在 0.99 前面」，没有规定这 213 首之间谁先谁后，取哪 10 首由 DBMS 决定。
- **改法**：加一个能唯一确定顺序的列作为第二排序依据，通常用主键：

  ```sql
  ORDER BY UnitPrice DESC, TrackId
  ```

- **放到分页里**：每翻一页都要重新执行一次查询，如果并列行的顺序在两次执行之间变了，就会出现同一首歌在第 1 页和第 2 页都出现、而另一首歌一页都没出现的情况。
