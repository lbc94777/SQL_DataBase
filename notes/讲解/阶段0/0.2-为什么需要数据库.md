# 阶段 0：为什么需要数据库

## 全貌

这一篇回答两个问题：

1. **数据为什么不能直接存在 CSV 或 Excel 里？** 用的人一多、数据量一大，直接操作文件会出哪些事？
2. **"数据库"到底指什么？** `chinook.db`、`sqlite3.exe`、Python 的 `sqlite3` 模块，分别是什么角色？

第一个问题是整条学习路线的出发点：后面的建模、约束、索引、事务，每一项都在解决这里出现的某个问题。所以这里只讲清楚"问题是什么"，至于"具体怎么解决"，留到对应的阶段再深入。

下面用选课系统做例子。假设先不用数据库，所有数据都存在 CSV 文件里：`students.csv` 存学生，`enrollments.csv` 存选课记录。

---

## 问题一：查找只能从头扫到尾

有 10 万名学生、100 万条选课记录，要查"学号 2023001 选了哪些课"。

用 CSV 的话，程序只能打开 `enrollments.csv`，**从第一行读到最后一行**，逐行比较学号。这就是线性扫描，复杂度 O(n)。100 万行就要扫 100 万次。数据量翻 10 倍，耗时也翻 10 倍。

数据库可以给学号这一列建立**索引**。索引的底层是 408 数据结构里学过的 B+ 树，查找复杂度是 O(log n)，数据量翻 10 倍时，耗时几乎不变。这部分在**阶段 5** 详细讲，还会做实验对比耗时。

### 更重要的启发：声明式和命令式

用 CSV 时，"怎么找"的代码要你自己写：打开文件、逐行解析、比较、收集结果。用 SQL 只需要写：

```sql
SELECT ... FROM enrollments WHERE student_id = '2023001';
```

你只说明**要什么**。至于**怎么找**，是逐行扫描还是走索引，由数据库管理系统自己决定。

这叫**声明式**语言，和 Python、C++ 这类**命令式**语言不同，后者要一步步告诉计算机怎么做。这是学 SQL 时最需要转变的思维方式。

> 你可能以为写 SQL 就像写 Python 函数，代码从上到下依次执行。其实 SQL 描述的是"想要的结果长什么样"，DBMS 会自己决定执行顺序和方法。比如 `SELECT` 写在最前面，实际执行时却不是第一步。这一点到 0.4 写查询时会具体看到。

## 问题二：两个人同时改，结果出错

两个学生同时抢最后一个名额：

```
进程 A：读文件，看到剩余名额 = 1
进程 B：读文件，看到剩余名额 = 1
进程 A：1 > 0，可以选，写回 剩余名额 = 0，A 选课成功
进程 B：1 > 0，可以选，写回 剩余名额 = 0，B 选课成功
```

名额只有 1 个，却选上了 2 个人，这就是**超卖**。

本质上这就是 408 操作系统里的临界区问题："读、判断、写"这三步不是原子操作，又没有互斥保护。

CSV 还有一个更糟的地方：文本文件基本无法"只改一行"，通常要把整个文件重写一遍。所以 B 写回时，可能把 A 刚写入的其他数据也整体覆盖掉。

数据库用**事务和锁**解决这个问题。这是**阶段 6** 的核心内容，到时会先亲手复现超卖，再把它修好。

---

## 问题三：写到一半崩溃，文件损坏

程序写文件写到一半崩溃或断电，文件可能只写了一半，最后一行被截断。如果是"先清空再重写"的写法，旧数据已经没了，新数据又没写完，**数据就丢了**。

数据库保证**原子性**：一组修改要么全部生效，要么全部不生效，不会停在中间状态。即使在写入时断电，重启后也会恢复到一致的状态。这是 ACID 中的 A，在**阶段 6** 讲。

---

## 问题四：非法数据没人拦

CSV 对内容没有任何要求，成绩填成 `abc`、`150`、`-3` 都能存进去。要拦住这些数据，只能在**每一个**写这个文件的程序里各自写校验代码。只要有一个程序漏写，或者有人直接用记事本打开修改，脏数据就进去了。

数据库可以把规则**定义在数据本身上**，比如"成绩必须在 0 到 100 之间"、"学号不能为空"、"学号不能重复"。之后不管是哪个程序、用什么方式写入，违反规则的数据**一律被拒绝**。这叫**约束**，在**阶段 2** 讲。

---

## 问题五：同一份数据存多处，改一处漏一处

一个学生的名字在 3 个文件里各存了一份。这个学生改名后，你改了 2 个文件，忘了第 3 个，数据就**互相矛盾**了：到底哪个才是真名？这叫**更新异常**。

> 你可能以为用了数据库，这个问题就自动消失了。其实**数据库本身解决不了它**：如果你在数据库里同样把名字存三份，照样会出现矛盾。

解决办法是**设计**：名字只存一份，其他地方用学号去引用它。这就是**阶段 1** 要学的建模和范式。所以阶段 1 是整个路线里最重要的阶段之一：工具再强，表设计错了也没用。

## 顺带一提：Excel

上面五个问题 Excel 基本都有。另外，Excel 一个工作表最多只能放 **1,048,576 行**，而例子里的 100 万条选课记录已经接近这个上限了。

## 数据库、DBMS、客户端

日常说"数据库"的时候，常常把三样东西混在一起：

- **数据库**：按一定结构组织起来的数据本身。
- **数据库管理系统**（DBMS）：负责存储、查询、维护数据的**软件**。上面提到的索引、事务、约束，都是 DBMS 提供的能力。
- **客户端**：让你发送 SQL、查看结果的程序。

对应到我们用到的东西：

- `chinook.db`：**数据库**。就是那个文件，里面装着数据。它是 SQLite 自定义的二进制格式，所以用 VS Code 直接打开只能看到乱码，必须通过 DBMS 才能读。
- `sqlite3.exe`：**客户端，并且内置了 SQLite 这个 DBMS**。
- Python 的 `sqlite3` 模块：**同样内置了一份 SQLite DBMS**，再加上一套 Python 接口。
- DBeaver：**客户端**。连接 SQLite 时用的驱动里也带着一份 SQLite 引擎。

SQLite 这类数据库叫做**嵌入式数据库**。它没有独立运行的服务进程，DBMS 就是一个函数库，**直接编译进**要用它的程序里。所以上面这几个程序各自带了一份 SQLite 引擎。

在你的电脑上就能看到证据：命令行里的 SQLite 版本是 **3.54.1**，Python 里内置的是 **3.49.1**。这是两份不同的 DBMS 副本，只是在操作同一个文件。

对比一下，阶段 7 的 MySQL 是**客户端/服务器**模式：DBMS 作为一个独立的服务进程一直在运行，客户端通过网络连接它。
